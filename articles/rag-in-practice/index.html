RAG2026.03.03

RAG 检索增强生成实战

从向量数据库选型到 Embedding 策略，完整构建一套企业级 RAG 系统。含 Pinecone、Weaviate 对比实测。

为什么需要 RAG？

即使 Gemini 3.1 Pro 拥有 2M 的超长上下文，大模型仍然存在知识截止日期和幻觉问题。RAG（Retrieval-Augmented Generation）通过检索外部知识库来增强模型的回答准确性。

核心架构

1. 文档处理

Chunking 策略是 RAG 系统性能的关键。推荐使用语义分块（Semantic Chunking）而非固定长度分块，保持语义完整性。

2. 向量数据库选型

  • Pinecone：全托管，开箱即用，适合快速原型
  • Weaviate：开源可自部署，支持混合搜索
  • ChromaDB：轻量级，适合本地开发和小规模应用
  • Qdrant：高性能，Rust 编写，适合大规模生产环境

3. Embedding 模型

OpenAI text-embedding-3-large 和 Cohere embed-v4 是目前最优的通用 Embedding 模型。中文场景推荐使用 BGE 或 M3E 系列。

优化技巧

  • Hybrid Search：结合关键词和语义检索
  • Re-ranking：使用 Cross-Encoder 对检索结果二次排序
  • Query Expansion：自动扩展用户查询以提升召回率
